Overview

omniline is a statusline framework for AI coding CLIs. Most of these tools render a statusline by invoking an external command on every prompt and feeding it a JSON payload on stdin — but each one shapes that payload differently, even for the same underlying concepts: model name, context usage, rate limits, git branch, and so on.

Rather than write a full statusline script per harness, omniline splits the problem in two: a set of shared, pure rendering and data-lookup primitives (ANSI colors, bar meters, rate-limit pacing, source lookups like git branch or account) that every harness reuses, plus one thin adapter per harness that maps its specific JSON shape onto those primitives.

Why bother splitting it this way? Duplicating the whole statusline per harness means the copies drift the moment one gets a feature the other doesn't — which is exactly how this repo started: a Claude-Code-only bash script and a half-finished Python rewrite silently diverged from each other, including a “quota” schema someone had guessed at and gotten wrong. Adapters keep the harness-specific mapping small and honest; everything else lives once.

For the full technical rundown of the module layout and how the pieces fit together, the README stays the canonical reference. This site is the friendlier walk through installing, understanding, and removing it.

Install

The one-liner:

curl -fsSL https://raw.githubusercontent.com/Deetss/omniline/main/install.sh | bash

This downloads omniline into ~/.local/share/omniline, then hands off to its interactive installer, which:

  • detects which of Claude Code / antigravity-cli / Codex are on this machine
  • shows any statusline each one already has configured
  • asks before touching anything, and backs up whatever it's about to overwrite first — always, never silently

Safe to run again later: it updates the existing copy in place instead of re-cloning, and re-running the installer just re-asks per harness.

Flags and environment variables

OptionPurpose
--dir <path> Where to install omniline. Defaults to ~/.local/share/omniline, or $OMNILINE_HOME if set.
--ref <branch> Branch to install. Defaults to main.
$OMNILINE_HOME Env var alternative to --dir for the install location.

Pass flags straight to the piped script, for example:

curl -fsSL https://raw.githubusercontent.com/Deetss/omniline/main/install.sh | bash -s -- --dir ~/tools/omniline --ref main

Prefer to read a script before piping it into bash?

Clone it and run the same installer directly — install.sh does nothing bin/install doesn't: 

git clone https://github.com/Deetss/omniline.git
cd omniline
python3 bin/install

Requirements

  • python3 ≥ 3.8
  • either git, or curl + tar (used as a fallback to download a source archive when git isn't available)

No third-party packages, nothing to compile.

Per-harness support

Confirmed against each harness's own docs or source, not assumed.

HarnessStatusline hookAdapter status
Claude Code ● arbitrary shell command, JSON on stdin Real, wired up
antigravity-cli ● same shape as Claude Code Real, verified against a live install
Codex ● no custom command — fixed field list only N/A — native config written directly

Claude Code

Uses statusLine.command in settings.json, with the JSON payload arriving on stdin. Fully wired up.

antigravity-cli

Same shape as Claude Code (statusLine.command in settings.json, or /statusline <path>). Originally built from the documented schema alone; now verified against a real install and a real payload, quota bucket rendering included.

Codex

Codex has no way to execute a script for its statusline. Confirmed against Codex's own source (codex-rs/tui/src/bottom_pane/status_line_setup.rs): only a fixed, kebab-case identifier list under [tui]/status_line in ~/.codex/config.toml is supported. This is tracked upstream as openai/codex#17827. Because there's no command hook to adapt to, Codex doesn't get an adapter — bin/install writes that native config.toml block directly instead, including its own item-order customization prompts.

Uninstall / Restore

Both are interactive, and both back up current state before changing anything:

python3 bin/uninstall   # back up current state, remove this framework's config
python3 bin/restore     # pick a backup for a harness, back up current state, restore it

Backup file naming

Backups are written to:

backups/<harness>-<original filename>.<timestamp>.bak

This directory is gitignored — it's machine-local, not something to commit. The harness prefix matters: Claude Code's and antigravity-cli's config files are both literally named settings.json, so without the prefix their backups would be indistinguishable from each other.

bin/restore lets you pick which backup to bring back for a given harness, and takes a fresh backup of whatever's currently in place before it restores — so restoring is never a one-way trip either.

Contributing / adding a harness

This site is aimed at people installing, configuring, and uninstalling omniline day to day. If you're looking to add support for a new harness or otherwise contribute code, the README's Adding a harness section walks through the full process: confirming the harness actually supports a custom command, capturing a real payload sample, writing the adapter, and wiring it into the installer and tests.
